# HACK-6 selection identity extension

This extends the final interpretation interface for the one-document editor adapter. The adapter may expose its complete text as paragraph `document`, preserving newlines. Numeric offsets remain UTF-16 code units.

For document text `We need selected text.`, a selection may carry three optional fields:

```json
{
  "type": "selection",
  "at_ms": 300,
  "paragraph": "document",
  "start": 8,
  "end": 21,
  "text": "selected text",
  "selection_id": "selection-2",
  "gesture_id": "action-7",
  "range_index": 0
}
```

Callers must supply offsets whose slice equals `text`. `selection_id` and `gesture_id` must be nonempty strings. `range_index` must be a nonnegative safe integer. Grouping is preserved without collapsing repeated gestures. The same selection ID may recur for the same exact range; using it for conflicting ranges in the supplied document state is rejected.

Both a reference and a working area may now carry `selection_id`:

```json
{
  "name": "reference_1",
  "paragraph": "document",
  "quote": "selected text",
  "selection_id": "selection-2"
}
```

The working-area object has the same fields except `name`. A non-null selection ID resolves the exact supplied selected occurrence: its paragraph and quote must equal the event's paragraph and selected text. The quote need not be unique elsewhere in the paragraph. No new numeric offsets or CRDT cursors are generated by the model.

A null or omitted output selection ID retains the original unique-quote rule. Strict model output schemas require the field with string-or-null type; the application validator still accepts legacy output objects that omit it. Old input selection events need no new fields.

An ID cannot authorize a larger or smaller area than its selection. A transformation combining several ranges uses distinct references carrying each selected ID and one contiguous working-area quote. If that expanded quote is unique, its selection_id is null. If the expanded area cannot be identified uniquely from existing selections, clarification is required. This does not introduce disjoint working areas.

The editor owns revision association, CRDT anchors, and mapping returned selection IDs back to captured ranges. HACK-6 only validates them against the supplied document state. The app must normalize historical selections into a consistent interpretation snapshot or retain enough anchor metadata to resolve them safely. This change does not implement that adapter or modify the store or scheduler.

Validation:

- `selection-identity-tests.log`: 33/33 deterministic interpretation tests, including all legacy tests.
- `evaluate_selection_identity.mjs`: two focused live-model checks, duplicate occurrence and grouped three-item reference resolution. Results and exact requests/responses are in `selection-identity-runs/` and `selection-identity-summary.json`.
- These tests use scripted capture events; fresh TTS, actual ASR, alignment, and app commit acceptance belong to the integrating editor task.
